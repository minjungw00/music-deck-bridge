# v1.0.2 release candidate

Prepared October 18, 2026 (Asia/Seoul). **Not published or submitted to either store.** The existing v1.0.1 GitHub release and Pending review Marketplace submission remain separate and unchanged.

## Scope and release-note draft

- Show Play when the selected player is paused and Pause while playing. Follow the player's reported state, including playback changes in Chrome, multiple toggle keys and keys returning to view. Offline keys show Play with the offline title.
- Match all seven action families and the Chrome popup to the main magenta play-disc brand. Keep the action-list icons monochrome and include separate 72px/144px Pause images.
- Include the maintainer-supplied thumbnail in the root README and document the existing Marketplace review and update investigation.
- Set source/Chrome versions to `1.0.2` and the plugin manifest to `1.0.2.0`. Preserve plugin/action UUIDs, authentication, shared port, protocol, configuration paths and permissions.

**Known limitation:** this release candidate does not contain an update-conflict fix. The October 18 [actual direct-update trace](update-procmon-2026-10-18.md) failed at the directory rename even after Node/console exit and a successful DELETE-access open by the host. A later [official-stop retry](update-procmon-retry-2026-10-18.md) installed 1.0.2 successfully with the same host running; the host removed the old folder recursively and deployed the candidate. The original rename denial's responsible component remains unknown. Detailed operation/settings retention and rollback remain unverified. See also [historical installer evidence](update-installation.md) and [lock diagnostics](update-lock-diagnostics.md). Maker Console DRM and store approval remain separate checks.

## Before touching the installed copy

1. Preserve the checksum-verified public [v1.0.1 packages](v1.0.1.md), including the plugin installer, Chrome ZIP and `SHA256SUMS.txt`, in a separate baseline/recovery directory. Candidate and baseline plugin installers have the same filename; never overwrite one with the other.
2. Record Windows, Chrome, Stream Deck software, device model/firmware, installed plugin/extension versions and installed plugin inventory. Check that the existing pairing and actions work before testing.
3. With Stream Deck fully stopped, privately back up the installed plugin folder, `%APPDATA%\MusicDeckBridge`, exported Stream Deck profiles and their profile data. Keep backups outside `Plugins`. Keep authentication/configuration contents and raw logs out of Git and release assets.
4. Preserve the same Chrome profile, extension ID and absolute unpacked-extension path. Record the existing custom port, profile actions, title mode and dial step. Verify the current token works without generating a new PIN; re-pairing would hide lost authentication.
5. Prepare timestamped Stream Deck logs and process/handle capture for the installation interval. If the rename fails, capture the process holding the directory at that moment (for example, with Process Monitor or handle inspection). A normal running plugin's current-directory lock does not identify the historical post-stop failure.

For the initial plugin comparison, leave Chrome at 1.0.1 to isolate the plugin installation. The extension runtime/protocol has not changed. Afterward, test Chrome 1.0.2 separately in the same unpacked directory and verify retention and the revised popup. Do not modify the Pending review v1.0.1 submission as part of this test.

Scenario B's official plugin-stop control requires developer mode. Preserve and restore the original setting if used, following the [controlled diagnostic record](update-lock-diagnostics.md); do not leave it enabled as an installation workaround.

For every scenario, record start/end timestamps, source commit/CI URL, both installer hashes, host state, plugin PID/exit timing, directory access/rename result, installed manifest before/after and success/failure log lines. Keep failures in the record even if a later recovery succeeds. Confirm the manifest and installed file bytes rather than relying on an installer dialog alone.

After each successful install and after rollback, verify the existing pairing **without a new PIN**, the matching custom port, profiles and all seven actions, custom title mode, dial step, album art and playback. Check toggle Play/Pause changes from both the key and Chrome, multiple toggle instances, returning keys, and the offline title/image. Check en/ko popup and installed icon rendering. Compare private state before/after without exposing credentials. If an update fails, verify recovery of the old installed version before continuing.
